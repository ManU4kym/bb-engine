# 🎯 BugCrowd Testing Guide & Report Generation

## Step 1: Find a BugCrowd Target

### Option A: Public Programs (No Approval Needed)

1. Go to <https://bugcrowd.com/programs>
2. Filter by:
   - **Status**: "Open" or "Active"
   - **Type**: "Public" (can test immediately)
   - **Scope**: Programs with public domains (<www.example.com>)
3. Click on the program to see:
   - Scope (in/out of scope URLs)
   - Submission guidelines
   - Reward levels
   - Previous vulnerabilities found

### Option B: Private Programs (Need Approval)

1. Browse same URL
2. Filter by "Private"
3. Apply to program
4. Wait for acceptance

### Recommended Starting Targets

- HackerOne/Bugcrowd's own public programs
- Well-known tech companies with mature programs
- Targets that accept vulnerabilities like: IDOR, XSS, SQLi, API issues

⚠️ **IMPORTANT**:

- ✅ Always check the scope before testing
- ✅ Only test authorized targets
- ✅ Read the program rules carefully
- ✅ Don't test during blackout periods

## Step 2: Run BB-Engine Against Target

### Example Command

```bash
# Replace https://example.com with your target
.\target\release\bb-engine.exe --config examples/config.yml discover \
  --target https://example.com \
  --wordlist examples/wordlist.txt \
  --depth 2
```

### Then Run Fuzzing

```bash
.\target\release\bb-engine.exe --config examples/config.yml fuzz \
  --target https://example.com/api/users?id=1 \
  --mode sqli
```

### Or Full Pipeline

```bash
.\target\release\bb-engine.exe --config examples/config.yml pipeline \
  --target https://example.com \
  --workflow examples/workflow.yaml
```

## Example Workflow

```
1. Find program on BugCrowd
2. Run: discovery --target https://target.com --wordlist wordlist.txt
3. Run: pipeline --target https://target.com --workflow workflow.yaml
4. Generate: python generate_report.py
5. Export: Open security_report.html in browser → Print to PDF
6. Submit: To BugCrowd with findings
```

## Tips for Best Results

✅ **DO:**

- Test during off-peak hours to avoid impact
- Document all steps
- Keep reports for proof
- Test comprehensively per rules
- Update wordlist with target-specific paths

❌ **DON'T:**

- Test outside scope
- Run excessive concurrent requests
- Modify production data
- Test without approval
- Exceed rate limits excessively
